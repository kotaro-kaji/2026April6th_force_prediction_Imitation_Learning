## 一番大事な答え

見た目が違っていても、物性だけのベクトルを得たいなら、 **外観と物性が統計的に独立になるようなデータ構成** が必要です。

つまり、最低限こういう構造が必要です。

$$
\text{appearance} \not\Rightarrow \text{physics}
$$

具体的には、

| 条件 | 必要な理由 |
| --- | --- |
| 同じ見た目で物性が違う | 見た目から物性を決め打ちできないようにする |
| 違う見た目で物性が同じ | 物性 latent が appearance latent にならないようにする |
| 未知 appearance × 既知/未知 physics のテスト | 本当に appearance に依存していないか見る |

だから、「見た目が全く同じ物体だけを集める」必要は必ずしもないです。  
でも、 **見た目と物性が一対一対応しているデータセットは絶対にダメ** です。

例えば、

- 赤い物体はいつも重い
- 青い物体はいつも軽い
- 大きい物体はいつも重心が右
- 木目の物体はいつも摩擦が高い

みたいになっていたら、どんなに損失を工夫しても、latent は appearance shortcut を使います。

## 物性 latent の作り方は「interaction encoder」にするのが自然

force imagination model にこだわらなくていいなら、かなり素直な形はこれです。

$$
d_i = E_\phi(\mathcal{H}_i)
$$

ここで、

$$
\mathcal{H}_i =
\{(s_t, a_t, F_t, \Delta s_t, \tau_t)\}_{t=1}^{K}
$$

です。  
つまり、物体 $i$ に対する数回の相互作用履歴から、物性 latent $d_i$ を推定する。

重要なのは、 **RGB画像そのものを $d_i$ の encoder に入れすぎないこと** です。入れるとしても、texture や object ID ではなく、

- 物体座標系
- 接触点
- 姿勢
- 形状
- 把持位置
- レバーアーム
- 関節角
- 行動
- 力/トルク
- 物体の動き

のような、力応答を解釈するために必要な幾何・運動情報に絞る。

例えば、

$$
d_i =
E_\phi(
\{p_t^{obj}, a_t, F_t, \tau_t, \Delta x_t, \Delta R_t\}_{t=1}^{K}
)
$$

みたいな形です。

この $d_i$ は「この物体の見た目」ではなく、「この物体は押す/持つ/引くとどう反応するか」の要約になります。

DensePhysNet も、複数ステップの動的相互作用から物体の物理表現を学習し、視覚表現と物理表現を分ける設計を入れています。EDO-Net も、布状物体に対して探索的な pulling interaction から物性 latent を得て、その latent を dynamics prediction に使う構成です。あなたの方向性はこの系譜に近いですが、力/トルク誤差によるオンライン更新と imitation policy への接続を主張点にできます。

## たぶん一番よい定式化

あなたの研究では、latent をこう定義するとよいです。

$$
d_i
=
\arg\min_d
\sum_t
\mathcal{L}
\left(
y_t,
f_\theta(g_t, x_t, a_t, d)
\right)
$$

ここで、

- $g_t$ ：見えている幾何情報、形状、姿勢、接触点
- $x_t$ ：proprioception
- $a_t$ ：行動
- $y_t$ ：観測された interaction outcome  
	例：force, torque, slip, object motion, deformation, lift success
- $d$ ：見た目では説明できない hidden physics latent

です。

つまり、

$$
\text{observed geometry} + \text{action} + \text{latent physics}
\rightarrow
\text{interaction response}
$$

というモデルにする。

このとき、 $d_i$ は「見た目から推定された特徴」ではなく、

$$
\text{実際に触ったときの予測誤差を最小化するために必要な低次元変数}
$$

になります。

これはあなたの元の force imagination とかなり相性がいいです。

## ただし、geometry と physics は分けた方がいい

ここがかなり大事です。

物体ごとの違いには、

1. 見えている違い  
	例：長さ、幅、形状、姿勢、接触点、把持位置
2. 見えていない違い  
	例：質量、重心、慣性、摩擦、剛性、内部抵抗

があります。

全部を $d_i$ に入れると、「物性 latent」ではなく「物体 latent」になります。

だから構造としては、

$$
z_i^{vis} = E_{vis}(o_i)
$$
 
$$
d_i^{phys} = E_{phys}(\mathcal{H}_i)
$$
 
$$
\hat y_t =
f_\theta(z_i^{vis}, g_t, x_t, a_t, d_i^{phys})
$$

と分けるべきです。

ただし、さらに強くするなら、 $d_i^{phys}$ には RGB appearance を直接入れない。  
あるいは入れるとしても、adversarial loss で object ID や texture が読めないようにする。

Domain-adversarial training では、タスクに有用だが domain を識別できない表現を作る考え方が使われます。この発想を借りると、 $d_i^{phys}$ から object ID や appearance class が予測できないように制約できます。

## 具体的な loss はこうなる

例えば、物性 latent を得るための loss はこうできます。

$$
\mathcal{L}
=
\mathcal{L}_{pred}
+
\lambda_{BC}\mathcal{L}_{BC}
+
\lambda_{reg}\mathcal{L}_{latent}
+
\lambda_{con}\mathcal{L}_{contrast}
-
\lambda_{adv}\mathcal{L}_{objID}
$$

意味はこうです。

$$
\mathcal{L}_{pred}
=
\|y_t - \hat y_t\|^2
$$

これは force / torque / motion / slip / deformation などの予測誤差。

$$
\mathcal{L}_{BC}
$$

これは imitation policy の損失。

$$
\mathcal{L}_{latent}
$$

これは latent を小さく、安定に、低次元に保つ正則化。

$$
\mathcal{L}_{contrast}
$$

これは「同じ物性なら近く、違う物性なら遠く」にする損失。

$$
\mathcal{L}_{objID}
$$

これは object ID classifier の損失。  
ただし encoder 側から見ると、object ID を当てられないように逆向きに最適化する。

つまり、

$$
d_i^{phys}
$$

から object ID, texture, shape category が読めないようにする。

- 黒いリモコン風
- 白いリモコン風
- 木目風
- アルミ風
- プラスチック風
- 少し丸みのあるもの
- 角張ったもの

- 重心が左
- 重心が中央
- 重心が右
- 軽い
- 重い
- 慣性が大きい
- 摩擦が高い
- 摩擦が低い

そして、外観と物性を独立に組み合わせる。

つまり、

| appearance | CoM |
| --- | --- |

| 白リモコン | 右 |

| 木目リモコン | 右 |

みたいにする。

長い直方体なら、かなり良い実験物体が作れます。

- 質量も軽い/重いに変えられる
- 可能なら慣性も変えられる

これを複数 appearance で用意する。

この場合、データ設計としてはかなり強いです。

$$
\text{appearance} \perp \text{hidden physics}
$$

を実験的に作れるからです。

## 「見た目が違っても物性だけを取る」ための encoder 構造

おすすめは、interaction の集合を食べる encoder です。

$$
e_k = \phi(p_k^{obj}, a_k, F_k, \tau_k, \Delta x_k)
$$
 
$$
d_i = \rho\left(\sum_{k=1}^{K} e_k\right)
$$

この形だと、複数回の probing interaction を順序に依存しない集合として扱えます。Deep Sets は、集合に対する permutation-invariant な関数を扱う代表的な枠組みです。

時系列順序が重要なら RNN / Transformer でもいいですが、物性推定としては set encoder の方が「何回か触った結果の統合」という意味が出しやすいです。

「latent が本当に物性を持っている」ことを示す証拠になるからです。

ただし、policy には ground truth 物性を直接渡すのではなく、実行時には interaction から推定した $d_i$ を渡す。  
評価時にだけ、latent から CoM や mass が decode できることを見せる。

EDO-Net も、明示的な物性ラベルなしで latent を学習しつつ、後から simulation の ground-truth physical parameters が latent から読めるかを評価しています。

## 「force imagination」ではなく「residual identification」と言った方がよいかもしれない

あなたの元の表現だと、

$$
F_{imagined}
$$

が中心でした。

でも今の問題意識では、もっと広く、

$$
\text{interaction residual}
$$

を使って hidden physics を推定する、と言った方が強いです。

つまり、

$$
\hat y_t = f_\theta(o_t, a_t, d_i)
$$
 
$$
d_i \leftarrow d_i - \alpha \nabla_{d_i}
\mathcal{L}(y_t, \hat y_t)
$$

ここで $y_t$ は force だけでなくてもよい。

- force
- torque
- object motion
- slip
- acceleration
- deformation
- lift tilt
- contact loss
- tactile image
- success/failure signal

でもよい。

こうすると、研究の主張が、

> force imagination

から、

> interaction-grounded object property identification

に広がります。

---

## ただし、latent を「物性だけ」にするのは原理的には保証できない

ここは正直に整理した方がいいです。

完全に unsupervised に、

$$
d_i = \text{pure physical property}
$$

を保証するのは難しいです。

なぜなら、同じ prediction loss を下げる表現は複数あり得るからです。  
例えば object ID を覚えても prediction loss は下がります。

だから論文では、

> We do not assume that the latent recovers human-interpretable physical parameters exactly. Instead, we learn a compact, interaction-derived context that captures task-relevant hidden physical properties while being regularized to be invariant to appearance and object identity.

くらいが安全です。

日本語で言うと、

> 本研究の latent は、厳密な物理パラメータそのものではなく、タスク遂行に必要な hidden physical response を圧縮した interaction-derived latent である。ただし、データ設計と正則化により、外観や object ID ではなく物性差を表すように誘導する。

です。

この言い方が一番安全です。

## あなたの研究に合う最終形

たぶん、今の方向だとこういう形が一番よいです。

### 1\. Probing / interaction phase

ロボットが対象を少し持つ、押す、傾ける、引く。

$$
\mathcal{H}_i =
\{o_t, q_t, a_t, F_t, \tau_t, \Delta x_t\}
$$

を得る。

### 2\. Object property inference

$$
d_i = E_\phi(\mathcal{H}_i)
$$

または、

$$
d_i \leftarrow d_i - \alpha \nabla_{d_i}
\mathcal{L}_{interaction}
$$

で latent を更新する。

### 3\. Non-contact / regrasp phase

この時点では force がない。

でも、

$$
d_i
$$

を保持している。

### 4\. Policy phase

$$
a_t = \pi_\theta(o_t, q_t, d_i)
$$

として、持ち直し位置、把持点、両手の配置、持ち上げ方を変える。

ここがあなたの研究の強い主張になります。

つまり、

> その瞬間の force feedback で反応するのではなく、過去の接触から推定した object-level physical latent を保持し、force が存在しない regrasp / repositioning / pre-contact planning 区間でも行動を変える。

これなら「force を直接 policy に入れればいいじゃん」への反論がかなり強くなります。

---

## 研究名としてはこういう方向

「force imagination」より、少し名前を変えた方が通りがいいかもしれません。

例えば、

- **Interaction-Grounded Object Property Latent**
- **Persistent Physical Context for Imitation Learning**
- **Residual-Based Physical Context Adaptation**
- **Contact-Inferred Object Context for Regrasping**
- **Learning Persistent Hidden-Physics Latents from Interaction Residuals**

個人的には、今の主張なら、

> **Persistent Physical Context for Regrasping from Interaction Residuals**

がかなり近いです。

「力を想像する」よりも、

> 接触中に hidden physics を同定し、非接触の持ち直し区間で使う

という研究に見えるからです。

## 結論

見た目が違う物体からでも、物体特有の物性ベクトルは作れます。  
ただし、普通に End-to-End で学習すると object ID latent になります。

必要なのは、

1. appearance と physics を独立に組み合わせたデータセット
2. interaction history から latent を推定する encoder
3. visual/geometry latent と physical latent の分離
4. object ID を latent から読めないようにする adversarial / contrastive 制約
5. 物性ラベルが取れるなら、一部 supervised な検証
6. force がない時間にも latent を保持して policy に使うタスク設計

です。

あなたの研究の中心は、

$$
\text{forceを使う模倣学習}
$$

ではなく、さらに一般化して、

$$
\text{interaction residualから persistent object physics latent を推定し、持ち直しに使う模倣学習}
$$

にするとかなり自然だと思います。
